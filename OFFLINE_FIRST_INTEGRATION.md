# Offline-First Integration Guide

This guide explains how to integrate the new offline-first architecture into the existing Kanban Order Management application.

## Overview

The application has been refactored to support offline-first functionality. All data is now stored locally using Drift/SQLite, and synchronization with the server happens automatically in the background when connectivity is available.

## New Components

### 1. Database Layer (`lib/database/app_database.dart`)
- **AppDatabase**: Main Drift database class
- **Tables**: Orders, OrderItems, Products, Customers, Users, SyncQueue, Settings, AuditLogs
- **Generated file**: `app_database.g.dart` (auto-generated by build_runner)

### 2. Services

#### Connectivity Service (`lib/services/connectivity_service.dart`)
Monitors network connectivity status and notifies listeners when connection changes.

**Usage:**
```dart
final connectivity = ConnectivityService();
print(connectivity.isOnline); // bool
connectivity.addListener(() {
  print('Connection changed: ${connectivity.isOnline}');
});
```

#### Sync Engine (`lib/services/sync_engine.dart`)
Handles automatic synchronization of local changes with the server.

**Usage:**
```dart
final syncEngine = SyncEngine(
  database: database,
  connectivity: connectivityService,
  token: userToken,
);

// Sync status
print(syncEngine.isSyncing);
print(syncEngine.pendingOperationsCount);

// Force sync
await syncEngine.forceSync();
```

#### Image Cache Service (`lib/services/image_cache_service.dart`)
Caches images locally for offline access.

**Usage:**
```dart
final imageCache = ImageCacheService();
final cachedFile = await imageCache.cacheImage(imageUrl);
await imageCache.preloadImages([url1, url2, url3]);
```

#### Secure Storage Service (`lib/services/secure_storage_service.dart`)
Encrypts and stores sensitive data like tokens and passwords.

**Usage:**
```dart
final secureStorage = SecureStorageService();
await secureStorage.saveToken(token);
final token = await secureStorage.getToken();
```

### 3. Repository Layer (`lib/repositories/local_repository.dart`)
Provides a clean abstraction over the local database.

**Usage:**
```dart
final localRepo = LocalRepository(database);

// Orders
final orders = await localRepo.getAllOrders();
await localRepo.insertOrder(order, needsSync: true);

// Products
final products = await localRepo.searchProducts(query);

// Customers
final customers = await localRepo.getAllCustomers();
```

### 4. Providers

#### Offline Orders Provider (`lib/providers/offline_orders_provider.dart`)
Replacement for the existing `OrdersProvider` that uses local database as primary data source.

**Usage:**
```dart
final offlineProvider = OfflineOrdersProvider(
  database: database,
  connectivityService: connectivityService,
  token: userToken,
);

// Load orders (from local first, then sync)
await offlineProvider.loadAllColumns();

// Perform transition (queues sync operation)
await offlineProvider.performTransition(
  orderId: orderId,
  nextStatus: OrderStatus.IN_COLLECTION,
);
```

### 5. UI Components

#### Sync Status Indicator (`lib/widgets/sync_status_indicator.dart`)
Shows sync status for individual items or the entire application.

**Usage:**
```dart
// Individual item status
SyncStatusIndicator(status: SyncStatus.pending)

// Connectivity status
ConnectivityStatusIndicator(isOnline: true, showLabel: true)

// Full status bar
SyncStatusBar(
  isOnline: connectivity.isOnline,
  isSyncing: syncEngine.isSyncing,
  pendingCount: syncEngine.pendingOperationsCount,
  onRetry: () => syncEngine.forceSync(),
)
```

## Integration Steps

### Step 1: Initialize Services in main.dart

```dart
import 'package:korzinkab_mobile/database/app_database.dart';
import 'package:korzinkab_mobile/services/connectivity_service.dart';
import 'package:korzinkab_mobile/services/secure_storage_service.dart';

void main() async {
  WidgetsFlutterBinding.ensureInitialized();
  
  // Initialize database
  final database = AppDatabase(_openConnection());
  
  // Initialize connectivity service
  final connectivityService = ConnectivityService();
  
  // Initialize secure storage
  final secureStorage = SecureStorageService();
  
  runApp(MyApp(
    database: database,
    connectivityService: connectivityService,
    secureStorage: secureStorage,
  ));
}
```

### Step 2: Update Provider Setup

Replace the existing `OrdersProvider` with `OfflineOrdersProvider` in your provider tree:

```dart
MultiProvider(
  providers: [
    ChangeNotifierProvider(
      create: (_) => AuthProvider(
        authRepository: authRepository,
        secureStorage: secureStorage,
      ),
    ),
    ChangeNotifierProvider(
      create: (_) => OfflineOrdersProvider(
        database: database,
        connectivityService: connectivityService,
        token: context.read<AuthProvider>().token ?? '',
      ),
    ),
    // ... other providers
  ],
  child: MyApp(),
)
```

### Step 3: Add Sync Status Indicator to UI

Add the `SyncStatusBar` widget to your main screen or app bar:

```dart
@override
Widget build(BuildContext context) {
  final connectivity = context.watch<ConnectivityService>();
  final ordersProvider = context.watch<OfflineOrdersProvider>();
  
  return Scaffold(
    appBar: AppBar(
      title: Text('Orders'),
      bottom: PreferredSize(
        preferredSize: Size.fromHeight(40),
        child: SyncStatusBar(
          isOnline: connectivity.isOnline,
          isSyncing: ordersProvider.syncing,
          pendingCount: ordersProvider.pendingSyncCount,
          lastError: ordersProvider.error,
          onRetry: () => ordersProvider.forceSync(),
        ),
      ),
    ),
    // ... rest of your UI
  );
}
```

### Step 4: Update Auth Provider (Already Done)

The `AuthProvider` has been updated to support offline login. It now:
- Restores session from local storage immediately
- Verifies token in the background without blocking
- Falls back to local data if network is unavailable

### Step 5: Handle Offline Scenarios in UI

Add offline indicators to screens that require network:

```dart
Widget build(BuildContext context) {
  final connectivity = context.watch<ConnectivityService>();
  
  if (!connectivity.isOnline) {
    return OfflineBanner(
      message: 'You are offline. Changes will sync when connection is restored.',
    );
  }
  
  // ... rest of UI
}
```

## Data Flow

### Reading Data (Offline-First)
1. UI requests data from Provider
2. Provider reads from Local Repository
3. Local Repository queries Drift Database
4. Data returned to UI instantly
5. Sync Engine triggers background sync if online

### Writing Data (Offline-First)
1. User performs action (e.g., change order status)
2. Provider updates Local Database immediately (optimistic update)
3. Provider queues sync operation in SyncQueue
4. UI reflects change instantly
5. Sync Engine processes queue when online
6. Server updated, local sync status cleared

## Sync Queue Operations

The sync queue supports the following operations:
- `create`: Create new entity
- `update`: Update existing entity
- `delete`: Delete entity
- `transition`: Change order status
- `attachCart`: Attach cart to order
- `detachCart`: Detach cart from order
- `markPaid`: Mark order as paid
- `unmarkPaid`: Mark order as unpaid
- `updateItem`: Update order item

## Conflict Resolution

The sync engine uses **Last Write Wins** strategy based on `syncedAt` timestamp:
- When downloading from server, if server data has newer `syncedAt`, it overwrites local
- When uploading to server, server data is considered authoritative
- Failed operations are retried with exponential backoff (max 10 retries)

## Incremental Sync

The sync engine implements incremental sync:
- Only fetches data changed since last successful sync
- Uses `last_sync_timestamp` setting to track sync state
- Reduces bandwidth usage and sync time

## Testing Offline Functionality

### Manual Testing Scenario

1. **Login while online**
   - User logs in successfully
   - Data synced to local database

2. **Go offline**
   - Disable network connection
   - App continues to work with local data

3. **Create orders offline**
   - Create new orders
   - Orders saved to local database
   - Sync operations queued

4. **Edit orders offline**
   - Change order statuses
   - Update order details
   - Changes reflected immediately

5. **Close and reopen app**
   - All offline changes preserved
   - App loads from local database

6. **Go online**
   - Connection restored
   - Sync Engine automatically processes queue
   - All changes synced to server

7. **Verify server**
   - Check that all offline changes are reflected
   - No duplicate records
   - No data loss

## Performance Optimizations

1. **Database**: WAL mode enabled for better concurrency
2. **Image Caching**: Memory + disk cache with size limits
3. **Sync**: Batch operations, incremental sync
4. **UI**: Optimistic updates for instant feedback

## Security

1. **Tokens**: Stored in Flutter Secure Storage (encrypted)
2. **Sensitive Data**: Use SecureStorageService for passwords, tokens
3. **Database**: Consider encrypting at rest for production

## Migration Notes

### Existing OrdersProvider
The existing `OrdersProvider` is still available. You can:
- Keep both providers and migrate gradually
- Replace entirely with `OfflineOrdersProvider`
- Use `OfflineOrdersProvider` as a drop-in replacement

### API Services
Existing API services (`OrdersService`, `AuthService`) are still used by:
- Sync Engine for server communication
- Auth Provider for login
- They are not replaced, only complemented

## Troubleshooting

### Build Errors
If you encounter build errors after adding new dependencies:
```bash
flutter clean
flutter pub get
flutter pub run build_runner build --delete-conflicting-outputs
```

### Database Issues
If database schema changes:
1. Increment `schemaVersion` in `AppDatabase`
2. Add migration logic in `onUpgrade`
3. Re-run build_runner

### Sync Issues
If sync fails:
1. Check connectivity status
2. Check token validity
3. Review sync queue for failed operations
4. Use `forceSync()` to retry
